# Rapport Technique : Conception et Développement d'une Solution IA

**Projet** : QHSE Air Bot (Assistant Intelligent Qualité Hygiène Sécurité Environnement)
**Bloc de Compétences** : n°1 - Conception et développement d’une solution d’intelligence artificielle

---

## 1. Contexte du Projet
Dans un environnement industriel de plus en plus contraint, les responsables QHSE (Qualité, Hygiène, Sécurité, Environnement) font face à une dispersion massive de l'information. Les données critiques sont éparpillées entre capteurs IoT (qualité de l'air), bases de données gouvernementales (accidents industriels ARIA) et sources réglementaires (Code du Travail, INRS). Cette fragmentation rend la veille réglementaire et la prévention des risques fastidieuses et sujettes à l'erreur humaine.

## 2. Problématique
**Comment centraliser et valoriser des données hétérogènes pour permettre une prise de décision proactive en matière de sécurité environnementale ?**

Le défi technique réside dans l'automatisation de la collecte de données disparates (API, Scraping, Fichiers), leur normalisation pour permettre des croisements intelligents (ex: lien entre pollution et accidents), et leur mise à disposition sécurisée.

## 3. Solution Apportée
Le **QHSE Air Bot** est une plateforme intégrée qui :
1.  **Automatise la collecte** (ETL) de données environnementales et juridiques.
2.  **Standardise l'information** pour permettre des analyses croisées.
3.  **Expose les résultats** via une API sécurisée et un assistant conversationnel (RAG).

## C1 – Automatiser l’extraction de données

**Objectif** : Créer des scripts d'extraction automatisés depuis des sources hétérogènes (API, Web, Fichiers) avec une gestion robuste des erreurs et une exécution planifiée.

### Implémentation
Le projet intègre un pipeline ETL (Extract-Transform-Load) complet qui collecte des données depuis 4 sources distinctes via la classe `DataCollector` ([src/etl/collect.py](src/etl/collect.py)) :

1.  **WAQI (World Air Quality Index)** :
    *   **Pourquoi cette source ?** : Fournit le **contexte environnemental temps réel**. Indispensable pour alerter les utilisateurs en cas de pic de pollution immédiat pouvant aggraver un incident industriel.
    *   **Méthode** : API REST (`requests`) avec gestion du rate-limiting (`time.sleep`).
    *   **Données** : Indices de qualité de l'air (AQI) et concentrations de polluants (PM2.5, PM10, NO2, O3, SO2) pour 50 villes françaises.
    *   **Technique** : Appel dynamique sur le endpoint `/feed/{city}/`.

2.  **Code du Travail Numérique** :
    *   **Pourquoi cette source ?** : Constitue le **socle juridique (Hard Law)**. Le chatbot doit impérativement citer les articles de loi exacts (R4222-*, R4412-*) pour garantir la conformité réglementaire des réponses.
    *   **Méthode** : Web Scraping (`BeautifulSoup`) sur le site officiel.
    *   **Données** : Articles réglementaires ciblés (Aération, Risques Chimiques, Amiante).
    *   **Technique** : Extraction structurée du titre et du contenu des articles HTML.

3.  **INRS (Institut National de Recherche et de Sécurité)** :
    *   **Pourquoi cette source ?** : Apporte les **bonnes pratiques (Soft Law)**. Là où le Code du Travail fixe les obligations, l'INRS explique "comment faire" (guides techniques, fiches toxicologiques), enrichissant ainsi les conseils du bot.
    *   **Méthode** : Web Scraping (`BeautifulSoup`).
    *   **Données** : Guides de prévention et fiches de synthèse ("Ce qu'il faut retenir") sur les risques chimiques et biologiques.
    *   **Technique** : Ciblage des pages de synthèse pour constituer une base de connaissances RAG de qualité.

4.  **ARIA (Barpi)** :
    *   **Pourquoi cette source ?** : Offre le **Retour d'Expérience (REX)** historique. Permet d'analyser les précédents accidents pour identifier des patterns de risques (ex: "Incendie usine Lubrizol") et proposer de la prévention prédictive.
    *   **Méthode** : Import de fichiers Open Data (CSV/Excel) via `pandas`. 
    *   **Données** : Historique des accidents industriels en France.
    *   **Technique** : Parsing robuste avec gestion de l'encodage `latin-1` et suppression des métadonnées (skiprows=7).

L'automatisation est assurée par un **Scheduler** (planificateur) intégré dans l'infrastructure Docker.

### Preuves de Code
*   **Extraction API (WAQI)** :  
    [src/etl/collect.py](src/etl/collect.py) (Fonction `collect_waqi` non visible mais classe `DataCollector` gère les appels API `requests`).
*   **Scraping Web (Code du Travail)** :  
    [src/etl/collect.py](src/etl/collect.py) (Lignes 32-50 : Méthode `collect_code_travail` avec liste des articles cibles R4222-*).
*   **Orchestration du Pipeline** :

## C2 – Requêtes complexes et manipulation de données

**Objectif** : Interroger et manipuler les données stockées pour répondre aux besoins métier (statistiques, filtrage).

### Implémentation
Utilisation de SQL via SQLAlchemy pour des requêtes analytiques.
Une requête clé du projet consiste à **croiser les données de pollution (WAQI)** avec les **accidents industriels (ARIA)** pour identifier les zones à double risque.

### Preuves de Code
*   **Exemple de Requête d'Agrégation Multi-Sources (SQL)** :
    Grâce à la standardisation (C3), nous pouvons effectuer cette jointure complexe :
    ```sql
    SELECT 
        w.ville, 
        AVG(w.aqi) as qualite_air_moyenne, 
        COUNT(a.id) as nombre_accidents_industriels
    FROM mesures_waqi w
    JOIN accidents_aria a ON w.ville = a.commune  -- Jointure possible car normalisé (UPPER)
    GROUP BY w.ville
    HAVING AVG(w.aqi) > 50; -- Filtre sur qualité dégradée
    ```
    *Cette requête démontre la capacité à lier des sources hétérogènes pour une analyse décisionnelle.*

*   **API Endpoint (Implémentation Python)** :
    [src/api/endpoints.py](src/api/endpoints.py) (Route `/stats/risks`) :
    ```python
    # Agrégation avec GROUP BY et COUNT
    db.query(MesureWAQI.niveau_risque, func.count(MesureWAQI.id)).group_by(...)
    ```

## C3 – Règles d’agrégation et nettoyage

**Objectif** : Transformer les données brutes en un format exploitable (nettoyage, standardisation, enrichissement).

### Implémentation
La classe `DataTransformer` assure la normalisation des données avant insertion en base, notamment pour permettre des jointures futures entre sources hétérogènes (ex: WAQI et ARIA).
*   **Nettoyage** : Trim des chaînes, gestion des valeurs nulles.
*   **Standardisation** : Conversion des champs de ville/commune en **MAJUSCULES** pour garantir la correspondance entre les sources (WAQI via `ville_recherchee`, ARIA via `commune`).
*   **Enrichissement** : Calcul automatique du "Niveau de Risque" pour la qualité de l'air.
*   **Optimisation (Sampling)** : Réduction intelligente des datasets volumineux (Accidents > 2000 lignes) pour garantir la performance des outils de monitoring.

### Preuves de Code
*   **Normalisation pour Agrégation (Villes en Majuscules)** :
    [src/etl/transform.py](src/etl/transform.py) (Méthodes `transform_aria` et `transform_waqi`) :
    ```python
    # Normalisation des champs de localisation pour jointure
    df['commune'] = df['commune'].astype(str).str.upper().str.strip()
    df['ville_recherchee'] = df['ville_recherchee'].astype(str).str.upper().str.strip()
    ```
    *Ces normalisations sont cruciales pour permettre la requête SQL de jointure (voir C2).*

*   **Transformation WAQI (Enrichissement)** :  
    [src/etl/transform.py](src/etl/transform.py) (Lignes 104-129 : Méthode `transform_waqi`).
    *   *Preuve* : Fonction locale `get_risk_level(aqi)` qui catégorise l'air en "BON", "MODÉRÉ", etc.

*   **Qualité des Données (Monitoring)** :  
    [src/data_monitoring/](src/data_monitoring/) (Scripts `quality` et `drift` utilisant Evidently AI).
    *Note* : Implémentation d'un sampling (2000 lignes) pour éviter la saturation mémoire/réseau sur les fichiers ARIA.

## C5 – Respecter les règles de conformité et de sécurité

**Objectif** : Sécuriser l'accès aux données (Authentification, Secrets) et assurer leur conformité (Qualité, Traçabilité, RGPD).

### Implémentation
*   **Authentification Forte** : Utilisation de JWT (JSON Web Tokens) pour sécuriser l'API.
*   **Protection des Données (RGPD)** : Les mots de passe sont hachés (Bcrypt) avant stockage.
*   **Gestion des Secrets** : Aucune clé en dur, utilisation exclusive de variables d'environnement (`.env`).
*   **Traçabilité** : Monitoring de la qualité des données (Drift detection).

### Preuves de Code
*   **Sécurité des Accès (Auth & Hashing)** :  
    [src/api/security.py](src/api/security.py) (Fonctions `create_access_token` et `get_password_hash` avec passlib/bcrypt).
    [src/api/auth.py](src/api/auth.py) (Endpoint `/login` et `/register` qui implémentent le hachage et la vérification).
    [src/api/conversations.py](src/api/conversations.py) (Protection des routes via `Depends(get_current_user)`).
*   **Gestion des Secrets (.env)** :  
    [.env](.env) (Fichier contenant `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `POSTGRES_PASSWORD`, etc.).
    [src/config.py](src/config.py) (Charge les variables via Pydantic `BaseSettings`).
*   **Conformité des Données** :  
    [src/data_monitoring/drift/waqi_drift.py](src/data_monitoring/drift/waqi_drift.py) (Détection automatique de dérive des données).
